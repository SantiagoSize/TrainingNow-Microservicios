DOCUMENTACIÓN API (Swagger / OpenAPI) - para mostrar al profe
====================================
Con los 4 microservicios corriendo localmente:

TrainNow-Usuarios (8081)        http://localhost:8081/swagger-ui.html
TrainNow-Biblioteca (8082)      http://localhost:8082/swagger-ui.html
TrainNow-Rutinas (8083)         http://localhost:8083/swagger-ui.html
TrainNow-Comunicaciones (8084)  http://localhost:8084/swagger-ui.html

JSON OpenAPI (para importar en Postman): reemplazar /swagger-ui.html por /v3/api-docs
en cada URL de arriba.

¿SEGURIDAD? Ahora sí hay Spring Security real, con filtro JWT propio
(JwtAuthenticationFilter) en los 4 servicios:
- TrainNow-Usuarios y TrainNow-Biblioteca: los endpoints administrativos exigen
  un token JWT de rol ADMIN a nivel de Spring Security (401 sin token, 403 con
  token de otro rol). Además se mantiene el chequeo manual que ya existía
  (requireActiveAdmin / JwtValidator.requireAdmin) como segunda capa, por si el
  admin fue baneado/suspendido después de sacar el token.
- TrainNow-Rutinas y TrainNow-Comunicaciones: siguen totalmente abiertos
  (permitAll), no tienen ningún endpoint restringido por rol.
- Todo lo que no está en la lista de abajo (login, registro, listar, buscar,
  chat, rutinas, asistencia, notificaciones) sigue libre, sin token.

Endpoints que SÍ exigen token de un ADMIN activo (header Authorization):
- TrainNow-Usuarios: POST /api/users/admin-create, PATCH /api/users/{id}/ban,
  /unban, /suspend, /unsuspend, POST y GET /api/audit-logs, GET /api/reports,
  PATCH /api/reports/{id}/resolve
- TrainNow-Biblioteca: POST/PUT/DELETE /api/categories/**, POST/PUT/DELETE
  /api/exercises/**

====================================
CÓMO CONSEGUIR Y USAR EL TOKEN JWT (Swagger / Postman)
====================================
1) Conseguir el token: POST http://localhost:8081/api/users/login con body
   {"email": "admin@trainingnow.com", "password": "Admin123"}
   La respuesta trae un campo "token" (JWT largo tipo xxxxx.yyyyy.zzzzz). Ese es
   el que se usa. Dura 24 horas (jwt.secret / EXPIRATION_MS en JwtService.java).
   Usa una cuenta ADMIN (admin@trainingnow.com o francisca.torres@trainingnow.com)
   para los endpoints de arriba - con un token de entrenador o usuario da 403.

2) En Swagger UI (Usuarios y Biblioteca): ahora SÍ hay botón "Authorize" (candado
   verde arriba a la derecha). Tócalo, pega SOLO el token (sin la palabra
   "Bearer", Swagger la agrega sola) y dale "Authorize". Desde ese momento
   todos los "Try it out" de esa pestaña ya mandan el header solos. Rutinas y
   Comunicaciones no tienen este botón porque no tienen nada que proteger.

3) En Postman: en la request, pestaña "Headers" → agrega la key "Authorization"
   con el value "Bearer <token>". O usando la pestaña "Authorization" de Postman:
   tipo "Bearer Token" y pegas SOLO el token (Postman agrega el prefijo "Bearer "
   solo). Cualquiera de las dos formas funciona igual.

4) El mismo token sirve para Usuarios y Biblioteca (comparten el mismo secreto
   HS256, jwt.secret). En Rutinas/Comunicaciones no hace falta mandarlo, no
   piden nada.

VALIDACIÓN: DOMINIOS DE CORREO PERMITIDOS (registro público)
====================================
Ejemplo de cambio "en vivo" simple para mostrar al profe: el registro público
(usuarios normales, NO el alta de staff por admin) solo acepta correos de
gmail.com, hotmail.com, outlook.com o yahoo.com. Está en dos capas:

- Backend (la que manda): TrainNow-Usuarios/src/main/java/com/tn/usuarios/
  service/UserService.java - constante DOMINIOS_PERMITIDOS + método
  isDominioPermitido(), llamado desde create(). Si el dominio no está en la
  lista, responde 400 con {"error":"Solo se aceptan correos de: ..."}.
- App (feedback inmediato, no reemplaza al backend): TrainingNow/app/src/main/
  java/com/shagox/apptrainingnow/domain/validation/Validators.kt - función
  validateEmailRegistro() (usada SOLO en el campo de registro, en
  AuthViewModel.onRegisterEmailChange). El login sigue usando validateEmail()
  a secas (sin restricción de dominio) para no bloquear a las cuentas
  @trainingnow.com de staff que ya existen.

Para agregar/quitar un dominio: editar el Set de ambos archivos (deben
coincidir). Para cambiar la regla completa (ej. "solo un dominio", "cualquiera
menos X"), la lógica está aislada en esos dos mismos lugares.
